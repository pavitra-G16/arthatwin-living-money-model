# Three-minute ArthaTwin demo script

## 60–90 second version

**0:00–0:10 — Frame it.** “ArthaTwin turns transaction exports and user assumptions into an inspectable cashflow model. Today’s shared demo uses fictional data.” Show the synthetic-data badge.

**0:10–0:28 — Read the month.** Select November 2026 and show 14 rows, ₹85,000 imported income, ₹34,006 expenses after refunds, ₹50,994 observed net savings, and ₹44,172 modeled surplus. Explain that observed records and profile assumptions are different inputs.

**0:28–0:43 — Show learning.** Open Transactions & Rule Memory. Explain that a category correction creates a deterministic reusable merchant rule and future matching preview; it is not an LLM.

**0:43–1:03 — Explore a scenario.** Cut dining by 30% or increase rent and compare baseline, simulated surplus, delta, and goal timing. These are mathematical scenarios, not predictions.

**1:03–1:20 — Close safely.** Show recurring evidence and the monthly report. “Payments suggest cadence, not usage. The model does not connect to a bank, advise on investments, or move money.”

**0:00–0:20 — Frame it.** “ArthaTwin turns imported transactions and user-confirmed assumptions into a living monthly cashflow model. It is educational, does not execute payments, and does not recommend securities. This workspace is using synthetic sample data.” Show the synthetic-data label.

**0:20–0:45 — Dashboard.** Pick November 2026. Explain that 16 synthetic rows cover two months, so November correctly shows 14. The verified live figures are ₹85,000 income, ₹34,006 expenses after refunds, ₹50,994 observed net savings, and ₹44,172 modeled surplus. Explain statement completeness is user-confirmed and savings are not a verified balance. Show fictional goals and inferred recurring-payment evidence/confidence.

**0:45–1:15 — Import review.** In a local demo instance, choose the sample CSV or paste a synthetic bank SMS. Show the preview counts, parsed merchant/category, duplicate flag and row issue. Select rows and confirm. For public-demo mode, explain that statement uploads are blocked to protect the shared dataset.

**1:15–1:35 — Correction loop.** Correct a merchant category, show the unlocked match count, saved rule and future matching preview. Point out the source label distinguishing a default merchant rule from a user-learned rule. Explain user-locked rows remain protected.

**1:35–1:55 — Recurring review.** Show observed cadence, dated payment count, qualitative confidence, and amount history. Mark a fictional service “No” only as a user statement. Explain this creates a scenario input; it is not proof of non-use.

**1:55–2:20 — Simulator.** Reduce dining or raise rent and compare the displayed baseline, simulated surplus, monthly delta, and goal timeline. Read the assumptions below the result; incomplete statements can make estimates misleading.

**2:20–2:40 — Coach.** Ask “How much did I spend in November?” Show the selected local tool and its verified result. If Gemini has been intentionally configured, obtain per-question consent before the optional call; otherwise show the deterministic response. Ask for a stock recommendation to demonstrate the guardrail.

**2:40–3:00 — Report and close.** Show the November report’s actual period, category breakdown and data-quality notes. Print/download it only after checking the browser print preview. Close with: “The coach explains deterministic cashflow calculations; profile assumptions and statement coverage are identified clearly, and the product does not move money.”

Use only fictional statements and data in any public recording. Live URL: https://arthatwin-living-money-model-2.onrender.com/. Public mode blocks statement imports and profile edits; all showcased live data must remain synthetic. The hosted Gemini provider is not configured; demonstrate deterministic coaching and describe Gemini as optional/unconfigured.
